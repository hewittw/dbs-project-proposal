POTENTIAL PROJECT A Claude Setup Builder: a harness marketplace

Your whole Claude setup.
Port it anywhere.

One line · the problem and the user

Problem: every time you start Claude somewhere new (a class, a lab, a job) you rebuild your whole setup by hand, and people who don't code think it's too complicated to even try. User: anyone who uses Claude in more than one place, from power users porting their own setups to beginners like my mom and sister who want a complete one ready to go.

Run one skill in the Claude you already use and your entire setup (instructions, skills, MCP servers, plugins, settings, memory) goes up to the site as one named setup. Install it in any new folder with one sentence, or browse a harness marketplace of other people's complete, ready-made setups.

1 · Upload · port your own One skill packs it all

Run /publish-setup. It bundles CLAUDE.md / AGENTS.md, every skill, MCP config, plugins, settings and permissions, hooks, agents and memory files. API keys become placeholders.

2 · Get · harness marketplace Whole setups, not pieces

Pick a setup, switch off what you don't want (down to single skills and MCP tools), then tell Claude “install the Lab setup” in a new folder. Use it on the site, or entirely from your own Claude through the site's MCP.

02 How it works

Upload. Share. Install.

  1. 01 · UPLOADRun one skill

    In your current Claude, /publish-setup packages the whole working setup, strips secrets and pushes it to the site.

  2. 02 · SHARE / BROWSEA page per setup

    Each setup gets a page listing everything inside it. Keep it private, or browse other people's in the marketplace.

  3. 03 · INSTALLOne sentence

    In a new folder: “install the Lab setup” (via the site's MCP or a one-line command). Claude is fully configured.

    03 What exists

    Who already does part of this

    Plugins and marketplaces share bundles someone sat down and authored. Skills hubs and MCP registries share single pieces. Nobody lets you snapshot the whole setup you're already using in one step, then reinstall it somewhere else or share it as a complete harness.

    PRODUCTWHAT IT DOESWHAT'S LEFT
    • Claude pluginsSTRONGEST COMPETITOR

      Anthropic's own bundles of skills, MCP servers, agents and hooks, shared through marketplaces. On claude.ai they install from Customize and sync to Claude Code.

      Someone has to author the bundle by hand. Your CLAUDE.md, memory and settings aren't captured, and claude.ai plugins are paid plans only.

    • claude.ai skills

      Upload a skill ZIP in Customize > Skills, on every plan.

      One skill at a time.

    • skills.sh · npx skills

      Directory plus CLI that installs skills into Claude Code, Codex, Cursor and more.

      Single skills, not a whole setup.

    • MCP Registry · Smithery

      Catalogs of MCP servers; Smithery can write the config for you.

      Single servers. Assumes you know what an MCP server is.

    • claude-code-templates

      Catalog of 1,000+ components installed with npx flags.

      Pieces from a catalog, not a snapshot of your own setup.

    • Profile switchers

      CLIs that swap whole ~/.claude folders per context.

      Whole setups, but local only: no upload, no sharing, developers only. Shows the need is real.

    • rulesync · Cursor plugins

      One rules file translated into CLAUDE.md, AGENTS.md, .cursorrules; Cursor's own bundles.

      Context only, or one tool only. The translator pattern is worth copying.

    Plan: work with Anthropic's formats, not against them. A setup stores the real files, and can be exported as a plugin, so if Anthropic ships more of this, setups still work.

    07 Open questions

    Open questions & risks

    • Q-01
      What's different from Claude plugins?

      Plugins are the closest thing and they're Anthropic's own, but someone has to author each one. My bet: snapshot the setup you already use, including CLAUDE.md, memory and settings, in one step. A setup can be exported as a plugin.

    • Q-02
      Who is it for?

      Power users porting their own setups (me), or non-technical people like Sister and Mom installing someone else's? v1 is porting your own; the marketplace is what could serve beginners.

    • Q-03
      Hardest part: which memory travels?

      Memory comes in two kinds. Memory rules are how I like Claude to work, like “ask before deploying” or “never send my email anywhere,” and they should travel with every setup. Context-specific memory is about one project, like file paths, deadlines and repo names, and it usually shouldn't. The goal is a setup that's more personal than a plugin but not tied to one exact file structure. On upload, the skill sorts memory into rules or context and lets me check what goes. For my own personal store I can sometimes keep an exact copy, file structure and all, but shared uploads only carry the rules.

    • R-01
      Secret leakage

      A live setup is full of API keys and tokens, in .mcp.json, settings and sometimes plain .md files. Upload must swap them for ${VAR} placeholders, show what it found, and never store the real values.

    • R-02
      Absolute paths

      Setups point at things like /Users/me/.... They need rewriting to relative or ~ paths on upload, or the install breaks on anyone else's machine.

    • R-03
      Setups depend on the machine

      Local MCP servers, CLIs and plugins may need Node, Python or a binary that's installed on my laptop but not yours. The setup page has to list those requirements, and install has to check for them.

    • R-04
      claude.ai can't write local files

      A remote MCP connector runs from Anthropic's cloud and can't write files on your computer. Free plans get one custom connector, and plugins need a paid plan. So install is Claude Code first; the claude.ai path is probably a download plus a connector that serves the setup in chat.

    • R-05
      Formats change fast

      Dad: it “needs to be resilient to change.” Plugins launched in Oct 2025 and later gained skills; slash commands folded into skills; .dxt was renamed .mcpb; the MCP spec has had four revisions since March 2025, several breaking. Fix: a versioned setup manifest plus translators.

    • R-06
      Trust

      Installing someone else's setup means their skills, hooks and MCP servers run as you. Only my own setups in v1, and Claude asks before each file write.

    • R-07
      MCP sign-in and free tiers

      OAuth discovery for remote MCP breaks easily. Supabase Free pauses after a week without activity, right over Thanksgiving. Vercel Hobby and Clerk's free 50k users are plenty.

    • R-08
      On-site agent cost and abuse

      Every lookup on the website is a paid model call. It needs sign-in, per-user rate limits and a hard spending cap, and the agent can only call the same search and install tools as the MCP.
